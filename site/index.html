Every setup gets
its own folder.

The vanilla launcher and most legacy launchers don't manage modpacks at all — they just point at one .minecraft. Prism, PolyMC and MultiMC do, but they lock you into their profile system. Elo works differently: it points your existing .minecraft at a different set of mods, resource packs, shaders and config, so moving between a heavy modpack and a clean vanilla world is a relink instead of another multi-gigabyte copy. No new launcher, no new Java, no duplicated worlds — and no profile lock-in.

install

curl -fsSL https://github.com/3nderXP/elo/releases/latest/download/install.sh | bash

Needs bash, curl and jq. Never asks for sudo, never touches your package manager, and never writes to .minecraft before you tell it to.

01

        
why

      


      

        
A launcher manages the game. Elo manages what is inside the folder.

        
Both jobs matter and they do not overlap. Elo never installs Java, never picks a Minecraft version, and never asks you to move your worlds into a launcher profile. It works on the content your launcher already reads.


        

          

            
Works with your launcher

            
The vanilla launcher and most legacy launchers don't manage modpacks — Elo adds that without replacing your launcher. Prism, PolyMC and MultiMC manage modpacks via profiles; Elo works at the content layer instead, so you keep your launcher and your profiles, and just swap the folder contents. Your .minecraft stays exactly where it is, and only the folders inside it become links.

          

          

            
Owns content, nothing else

            
Mods, resource packs, shaders, config and saves. Java, Minecraft versions, accounts and the game itself stay entirely your launcher's business.

          

          

            
Switching is a relink

            
Changing setups moves five symlinks. No copying, no duplicated worlds, no waiting on gigabytes to finish duplicating.

          

          

            
Knows if a file is still original

            
Every managed file is verified by SHA-512, so a mod you edited by hand is reported as modified instead of being silently replaced.

          

          

            
Refuses instead of overwriting

            
A name collision, an unknown symlink or a mismatched hash stops the command and tells you what it found.

          

          

            
Same engine, two front-ends

            
The guided menu and the command line call the same handlers, with the same checks and the same exit codes.

instances

      


      

        
Switching is a relink, not a copy

        
Elo keeps every setup under ~/.elo. The active one is exposed inside your existing .minecraft through links that Elo created, and can prove it created.

04

        
safety

      


      

        
Your Minecraft folder is your data, not Elo's

        
Elo never destroys something it cannot put back. Every destructive path has a reversible counterpart, and the reversible one is what runs by default.


        
    
          
  • Your original folders are moved aside once, and never overwritten.
    • 
          
  • Symlinks Elo does not own are reported, never removed.
    • 
          
  • Every managed addon is verified by SHA-512 before it is reused and before it is removed.
    • 
          
  • A file that already exists with a different hash stops the install as a collision, instead of being overwritten.
    • 
          
  • Removing a modified file requires you to name it explicitly with --file.
    • 
          
  • Commands that change something ask first. --yes is the only way past that, and you have to type it.
    • 
          
  • uninstall --purge refuses paths like / and $HOME.
    • 
          
  • Uninstalling keeps ~/.elo by default, so your instances survive.
    • 
        


        
      

    

  


  
  

    

      

        
05

        
requirements

      


      

        
Bring your own Minecraft folder

        
Elo does not install Minecraft, Java, mod loaders or launcher profiles. Set up the version and loader you want the way you already do, then point Elo at the result.


        

          

            
systems

            
Linux and macOS. Native Windows is not supported.

          

          

            
dependencies

            
bash curl jq tar sha256sum or shasum. Gum is downloaded privately by the installer and removed with Elo.

~/.local/share/elo for releases, ~/.local/bin/elo for the command.

06

        
faq

      


      

        
Short answers


        

          

            Do I have to replace my launcher?
            
No, and that is the point. Most launchers don't manage modpacks — the vanilla launcher, Legacy Launcher, Shiginima and others just point at one .minecraft. Prism, PolyMC and MultiMC do, but via profiles. Elo works at the content layer: it points your existing .minecraft at different mod sets, so switching between a heavy modpack and a clean world is a relink, not a multi-GB copy. No launcher lock-in, no profile migration.

          

          

            What happens to the mods folder I already have?
            
On first activation in safe mode, your real folders are moved to ~/.elo/backups/original and replaced with links that Elo owns. The backup happens at most once and is never overwritten. elo instances reset puts everything back.

          

          

            A file with that name already exists. Will it be overwritten?
            
No. If the existing file has exactly the expected name and SHA-512 hash, Elo reuses and records it. Otherwise the install stops with collision. Run elo addons list <instance> and decide explicitly.

          

          

            Something looks wrong. Where do I start?
            
Run elo status. It reports missing, broken, divergent and externally managed links. Use elo instances reset only after reading that diagnosis.

          

          

            Can I use it in scripts?
            
Yes. Commands are grouped and stable, --dry-run previews any change and --yes enables deliberate automation. Output is human-oriented; there is no JSON mode.

          

          

            Does it need root?
            
No. The installer never uses sudo and never changes your system package manager. Update and uninstall work without privileges.
